Installation

Requires Python 3.10+ and uv.

git clone git@github.com:boraderen/rheon.git
cd rheon
uv sync

Generate an example log with one drift per perspective (example/example.csv and example/example_meta.md):

uv run python example/generate_log.py

Run the tests:

uv run pytest

Quick start

Describe the drifts, then write a labeled log.

import rheon

drifts = [
    {"type": "control_flow", "mode": "sudden", "drift_point": 0.5, "num_activities": 9},
    {"type": "reassignment", "mode": "gradual", "start_point": 0.3, "end_point": 0.45},
    {"type": "amount", "mode": "sudden", "drift_point": 0.6, "mean": 4000},
]

rheon.generate_log(drifts, "out/example.xes", num_traces=2000, num_activities=8)

This writes the log out/example.xes and its ground truth out/example_meta.md. Read the log with pm4py:

import pm4py

log = pm4py.read_xes("out/example.xes")

Package structure

One public function, rheon.generate_log, on top of six modules.

rheon/
  __init__.py      exports generate_log
  config.py        column keys, labels, parameter validation
  drifts.py        drift validation and timeline helpers
  process_tree.py  build process trees and play out traces
  generator.py     the generation engine and generate_log
  metadata.py      build and render the ground-truth metadata
  write.py         write XES / CSV and the metadata sidecar
example/
  generate_log.py  one drift per perspective
tests/             pytest suite

API

rheon.generate_log(drifts, output_path, **options)

Writes the log and its metadata sidecar and returns None. Invalid options or drifts raise a ValueError before anything is written.

Argument Default Description
drifts—List of drift dicts; see Drift types.
output_path—Path of the log; its suffix is set by format.
log_namefile stemName used in the metadata and the sidecar filename.
format"xes""xes" or "csv".
num_traces1000Target number of cases (approximate).
num_activities10Activities in the base process tree.
num_resources8Resource pool res_01, res_02, …
num_regions4Regions region_1, region_2, …
tree_weights{"sequence": 0.6, "choice": 0.25, "parallel": 0.1, "loop": 0.05}Relative operator weights of the base tree; missing operators get 0.
start_date2020-01-01 UTCStart of the time horizon; naive datetimes are read as UTC.
end_date2020-12-31 UTCEnd of the time horizon.
activity_duration(30.0, 100.0)(mean, variance) of processing time in minutes; each activity's mean is drawn within ±40% of mean.
waiting_time(15.0, 50.0)(mean, variance) of the waiting gap before an event in minutes; per-activity means as above.
amount(1000.0, 40000.0)(mean, variance) of the case amount.

Cases start across [start_date, end_date] with a mean gap of (end_date − start_date) / num_traces before arrival-rate or workload changes. The first case starts exactly at start_date. The horizon bounds case arrivals; event completions can extend beyond end_date.

Generation workflow

The order used by the current generation engine.

  1. Check the output format, option names and base configuration, then validate and normalize drift dictionaries. Checks that depend on the evolving resource pool run during generation, before output is written.
  2. Build the base process tree and one tree per control-flow drift in chronological order. Each new tree must differ in its serialized representation from its predecessor; generation retries up to 100 times. Prepare a playout pool of max(200, num_traces) traces for each tree, filter empty traces, and fall back to the sorted activity list if a pool is empty.
  3. Initialize distributions for the union of activities across all tree versions. Duration and waiting means are drawn independently within ±40% of their base means; variances are shared across activities. Pick dominant resources and a dominant region.
  4. Generate arrivals using both arrival-rate and workload drift. At each current arrival cursor, sample an exponential gap whose mean is the current arrival-gap level divided by the current workload multiplier. A gap crossing a drift boundary uses the level at its starting cursor. Stop before the next arrival exceeds the horizon. Generation rejects more than 100 * num_traces + 1000 cases.
  5. For each arrival, select the process-tree version using the case start and sample a trace from its playout pool. Draw base durations, waiting gaps, resources, region and amount. Store the original event start times in base_starts; the first gap is zero.
  6. Apply reassignment, region, amount, waiting-time and pool-size drifts by start fraction. Ties retain input order. Apply all duration drifts afterward, also by start fraction, so a resource-specific slowdown follows the final resource assignment.
  7. Recompute final event timestamps from changed gaps and durations, round both timestamps to UTC whole seconds, and recompute duration from those timestamps. Assign sequential case and event identifiers, build metadata, write the log, then write its sidecar.

Event drifts use the stored, undrifted event start times throughout; final exported timestamps can cross drift boundaries after timing changes. Reference times and per-event drift labels are not exported. Workload changes arrivals during generation: there is no later case duplication, deletion or variant-preservation pass. Resources have no capacity constraint; activities are timed sequentially within each sampled trace.

Normal draws for durations, waiting gaps and amounts use the configured variance and are clipped below at 0.1. Gradual amount and waiting-time changes interpolate distribution means and variances before drawing new values; duration changes multiply existing values.

Drift modes

How the change is shaped over time.

Positions are fractions of the time horizon in (0, 1). Drifts on cases (process tree, amount, region, arrivals) follow the case's start time; drifts on events (resources, durations, waiting times) follow the event's start time before any drift is applied.

Mode Position keys Behavior
sudden drift_point The new behavior applies from drift_point on.
gradual start_point, end_point The change phases in linearly across the window: a new process tree, dominant resource or region is used with a probability rising from 0 to 1. Duration multipliers, arrival-gap levels and workload multipliers are interpolated. Waiting-time and amount means and variances are interpolated, then new values are drawn.

Drifts of the same type must not overlap or touch at an endpoint.

Drift types

The nine drifts and exactly what each one changes.

A drift is a dict with a type, a mode, its position keys and the type's parameters; any other key is an error. The perspective is a grouping only.

    {"type": "pool_size", "mode": "gradual", "start_point": 0.2, "end_point": 0.3, "delta": 2},
    {"type": "reassignment", "mode": "sudden", "drift_point": 0.4},
    {"type": "workload", "mode": "gradual", "start_point": 0.7, "end_point": 0.85, "workload_factor": 1.4},
    {"type": "duration", "mode": "sudden", "drift_point": 0.55, "resources": ["res_01", "res_02"], "factor": 1.8},
    {"type": "waiting_time", "mode": "gradual", "start_point": 0.45, "end_point": 0.6, "mean": 45},
    {"type": "amount", "mode": "sudden", "drift_point": 0.65, "mean": 3000, "variance": 90000},
    {"type": "arrival_rate", "mode": "sudden", "drift_point": 0.5, "factor": 0.5},

Output & metadata

An XES or CSV log and a readable ground-truth sidecar.

Each run writes two files next to output_path:

<name>.xes   (or <name>.csv)
<log_name>_meta.md

Log

Events carry event:id, concept:name, start_timestamp, time:timestamp (completion), event:duration_min and org:resource. Cases carry amount and region, which are case:amount and case:region in the CSV and in pm4py DataFrames. Timestamps are UTC, in whole seconds. The XES log also embeds the full metadata as JSON in the log attribute rheon:metadata.

The CSV has nine columns, in order: event:id, case:concept:name, concept:name, start_timestamp, time:timestamp, event:duration_min, org:resource, case:amount, case:region. In XES the case identifier is the trace's concept:name. Each activity occurrence is one event carrying both timestamps; there are no separate lifecycle rows. Amount and region are constant within a case. Amount is rounded to two decimals; duration is calculated in minutes from the rounded timestamps. Rows are ordered by case and event start.

Paper examples

The paper uses three CSV logs, each with one sudden drift at the midpoint of the 2020 horizon: control_flow.csv changes a five-step sequence into two three-step branches; resource_reassignment.csv uses three resources and changes the dominant resource for each activity; arrival_rate.csv increases the mean arrival gap by 20, reducing the configured arrival rate to 5% of its initial level. Each log has one plot: side-by-side directly-follows count matrices, side-by-side activity-resource frequency matrices, or a dotted chart. The matrices use the entire log, split by case arrival for directly-follows counts and by event start for activity-resource counts; the dotted chart orders cases by arrival.

Run uv run --with matplotlib python example/generate_paper_examples.py to regenerate logs, metadata, plots and tables; append --plots-only to use saved logs or --regenerate resource_reassignment to resample only the resource example. Settings, CSV hashes and measured results are recorded under paper/generated.

Metadata sidecar

  • General parameters: the run's parameters plus the generated trace, event and variant counts.
  • Base distributions: the base process tree, each activity's dominant resource and duration and waiting (mean, variance), plus the case amount, inter-arrival mean and dominant region.
  • Drifts: each drift's point or window (as fraction and timestamp) and exactly what it changed, before → after: process trees, resource maps, distributions or rates.
